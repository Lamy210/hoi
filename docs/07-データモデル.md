# 07. データモデル

- 作成日: 2026-11-14
- 状態: 確定（Phase 0 成果物 8/18）
- 方針: **データ指向設計（SoA）**。各ストアは構造体配列（typed array + parallel array）で保持し、IDは配列インデックス。エンティティクラスは持たない（docs/08）。

## 1. ID規約

| ID | 型 | 備考 |
| --- | --- | --- |
| ProvinceId | u32 インデックス | 0 は無効値（NULL_ID） |
| CountryId | u16 インデックス | 0 は「無主」 |
| UnitId | u32 | |
| BuildingId | u32 | プロヴィンス × 建物種でアドレス |
| CharacterId | u32 | 指揮官・指導者 |
| RegionId（州） | u16 | プロヴィンスの集約 |
| 財・産業・技術・イベントID | シナリオ文字列キー | ロード時に数値インデックスへ解決（data-driven） |

## 2. ストア一覧（Phase 1〜3 の中核）

### 2.1 ProvinceStore（SoA）

```text
owner: u16[]          # 領有国（de jure）
controller: u16[]     # 実効支配
cores: u16[][]        # コア国家のリスト（sparse）
terrainType: u8[]     # 8種
climate: u8[]         # 5種（表示・天候用）
infraLevel: u8[]      # 0-5
population: f64[]     # 総人口（整数をf64で保持: 2^53未満保証）
popDetail: 構造体配列  # 年齢3区分・識字率・雇用・生活水準・満足度（Phase 3）
areaKm2: f64[]
coastal: u8[]（bool）
capital: u8[]（bool）
victoryPoints: u16[]
deposits: 疎行列       # goodIdx → 基礎産出量
buildings: 疎行列      # buildingType → level（Phase 3）
regionId: u16[]
adjacency: CSR        # offsets[] + targets[] + cost[]（地理距離・infra重みは派生）
labelPoint: (f32,f32)[]  # ラベル表示点
```

### 2.2 CountryStore（SoA）

```text
nameKey, color, capitalProvinceId: u32[]
governmentType: u8[]        # シナリオ定義の政体種
treasury: i64[]             # クレジット（整数）
taxRates: f64[] × 税種
spending: f64[] × 部門
stability, approval, warSupport: f64[]
politicalPower: f64[]
manpowerPool: f64[]         #徴兵可能プール（Phase 2で計算化）
laws: 疎配列                 # lawSlot → enactedLawId
policies: 疎配列
techState: 完了技術集合 + 進行中（Phase 3）
market: 財ごと {stock, price, demand, supply}（Phase 3）
relations: 疎行列            # countryA × countryB → 関係値（Phase 2）
wars: 参加戦争リスト（Phase 1）
flags: 任意フラグ（イベント用）
```

### 2.3 UnitStore（SoA・師団）

```text
owner: u16[]
location: u32[]          # 現在のプロヴィンス
path: 移動残距離配列       # 目標パスはセグメント先頭プロヴィンス+残距離で表現
manpower: f64[]
equipment: 疎行列         # goodIdx → 数量
org: f64[]  strength: f64[]  experience: f64[]
commanderId: u32[]
stance: u8[]             # 移動/防御/攻撃/撤退
frontId: u16[]           # 所属戦線（Phase 2）
templateId: u16[]        # Phase 2
```

### 2.4 WarStore / DiplomacyState（Phase 1は簡易・Phase 2/4で拡張）

```text
War { id, participants:[CountryId], startTick, casusBelli, warScore, status }
Treaty { id, type, parties[], startTick, expiryTick|null, terms }
Claim { country, provinceId }
RelationEntry { a, b, value, 最近の履歴イベント[] }
```

### 2.5 SupplyGraph（logistics）

```text
nodes: { provinceId, capacity, isSource }
edges: プロヴィンス隣接から派生（infra重み）
distFromSource: f64[][]      # ソースごとの最短距離（週次再計算）
supplyEff: f64[][]           # province × country
```

### 2.6 MarketState（economy, Phase 3）

```text
goods: { key, basePrice, unit }  # シナリオ定義
per country: stock[good], price[good], demand[good], supply[good], importCap[good]
moneyLedgers: { gov, households, industry }  # 保存則検証用
```

### 2.7 イベント・AI状態

```text
EventRuntime: { activeEvents[], firedFlags[], cooldowns[] }
AiRuntime: { country → { lastThinkTick, stance, decisionLog(リングバッファ) } }
```

## 3. シナリオパックのデータ構造（data-pipeline / scenario-system）

```text
scenario-pack/
├── manifest.yaml        # 名前・バージョン・依存MOD・互換エンジン版
├── sources.json         # データ出典・ライセンス・取得日・品質フラグ
├── checksums.json       # SHA-256
├── map/
│   ├── provinces.json   # プロヴィンス定義（id, region, terrain, deposits, 都市点）
│   ├── geometry.lod{n}.bin  # 三角分割済みジオメトリ（LOD 1/2/3）
│   └── adjacency.json   # 隣接関係（検証済み）
├── countries/*.yaml     # 国家定義
├── goods/*.yaml         # 財定義
├── industries/*.yaml    # 産業・生産方法
├── techs/*.yaml         # 技術ツリー
├── focuses/*.yaml       # 方針ツリー
├── events/*.yaml        # イベント
├── stats/*.csv          # 正規化済み統計（quality_flag付き）
└── localization/{ja,en}.json
```

統計データの正規化スキーマ: `{entity_id(ISO3+ADM), year, indicator_key, value, unit, quality_flag(real|estimated|balanced), source_id, source_version}`（docs/12）。

## 4. セーブデータ構造（save-system）

```text
save file (.orbis):
├── header: { version(int), schemaHash, worldSeed, scenarioPackId, tick, createdAt }
├── stores: 各ストアの typed array をバイナリ（msgpackエンコード）
├── rngState: 世界+子ストリームの状態
├── commandLogTail: 直近のコマンド（デバッグ用・任意）
└── integrity: SHA-256(全体)
```

- バージョン移行は `migrations/v{n-1}_to_v{n}.ts` の連鎖で実施。読込時は header.version を検証し、不明バージョンは拒否（不正セーブ処理の要件）。
- リプレイファイルは `header + seed + コマンド列` のみ（Phase 5）。

## 5. 不変条件一覧（データレベル）

| ID | 不変条件 |
| --- | --- |
| INV-1 | 全プロヴィンスで `owner` は国家ID、`controller` は国家ID または NULL（無主） |
| INV-2 | 通貨の総量は不変（全帳簿の和が一定） |
| INV-3 | 状態の書き換えはコマンド経由のみ |
| INV-4 | 在庫・人口・兵力は負にならない |
| INV-5 | 隣接グラフは対称（A→BがあればB→A） |
| INV-6 | 同一tick内に同一コマンドの二重適用はしない（コマンドUID） |
| INV-7 | 財の時代出現はシナリオデータのみで決まる |
| INV-8 | セーブ→ロード後の状態ハッシュは元状態と一致 |

## 6. トレース構造（計算根拠）

導出値は「値＋ contributors 配列」を返す純関数で計算する。contributors は `{label, value, formula}`。UIは任意エンティティのトレースを要求時に再計算して取得（常時保持しないため性能影響ゼロ）。例: 師団の戦闘力 = 基礎強度 × 装備品質 × 地形 × 補給効率 × 指揮官 × 士気。各項が contributors に入る。
