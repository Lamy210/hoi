## 3. 所見

1. **ティアSのtick予算は大幅に余裕**がある。ボトルネックは描画側（GeoJSONパース・初回三角化）であり、LOD2を広域ズーム既定にした影響は小さい。
2. Worker境界のレイテンシはスナップショット配信方式（tick完了後にUIへ差分公開）で隠蔽され、×8相当（8日/秒）は平時・戦時とも問題なく達成可能な計算能力がある（ブラウザ実測はPhase 2）。
3. ティアM/L（3,000州/20,000州）の拡張は、データモデルがSoA＋CSRで設計されているため漸進的スケールが可能。ただしUIスナップショットの全配列複製はティアM以降で差分パッチ化が必要（docs/08 §5の設計どおり）。

| **50年完全リプレイ二重実行**（全月末アンカー一致） | 合格 | ✅ |
| **FPS（ヘッドレス・×8進行中・3秒計測）** | >45fps（E2Eゲート） | ✅ G2初回計測 |
| テスト | 43件（Vitest）+ 9件（E2E）全緑 | ✅ |

- ティアMのp99スパイクは週次の距離グラフ再計算（10国×2,500州のDijkstra O(n²)）。日次コストは容量係数のみ（0.13ms/日）に分離済み。バイナリヒープ導入でスパイク解消はPhase 3候補。
- Phase 2受入シナリオ「戦線を切った攻勢が補給断絶で崩壊する」: 統合テスト合格（京畿遮断→eff 0→包囲→崩壊、tests/integration/phase2.test.ts）。
- E2EのFPS自動計測を導入（×8進行中3秒間のrAF計測、>45fpsをゲート化）。G2は以後毎回検証される。
