## 0. 数値・単位の共通規約

本GDDおよび全仕様で用いる数値規約（docs/08 のエンジン設計と一致）。

- **時間**: 1 tick = 1日。シナリオ開始日を epoch とし、日付はプロレプティック・グレゴリオ暦で整数演算のみで変換する。
- **乱数**: シード付き PCG32。世界シードからシステム名で派生させた子ストリームを使用（`hash(worldSeed, "combat", unitId)`）。`Math.random` は禁止。
- **数値型**: 通貨・人口は整数（2^53 未満）。連続量（在庫・価格・効果）は float64 の仕様確定演算（`+ - * / 比較`）のみで計算し、`Math.sin` 等の超越関数はシミュ内で使用禁止（必要時は整数インデックスのテーブル＋線形補間）。
- **通貨**: 国際決済単位「クレジット」を共通抽象通貨とする（シナリオが表示名・換算を定義する。現代シナリオでは「百万USD相当」等）。為替はMVPでモデル化しない（判断 D-010）。
- **割合**: 0〜1 の浮動小数。表示時にUI層で整形する。

## 1. 世界地図（world-map / province-system）

### 1.1 管理する地理要素

| 要素 | 保有場所 | メモ |
| --- | --- | --- |
| 国家・州・プロヴィンス | province-store / country-store | プロヴィンスが最小空間単位。州(region)は集約単位（複数プロヴィンスのグループ） |
| 都市・首都・港湾・空港 | building-store + province フラグ | 首都は国の必須属性。港湾は海岸プロヴィンスの building |
| 鉄道・道路 | 補給グラフのエッジ属性 | MVPは infra level（0–5）として抽象、鉄道/道路の区別は Phase 2 |
| 海域 | province の terrainType=`ocean` | 海域はnaval movementグラフ（Phase 4）。MVPは移動不可の障害物 |
| 河川・山岳・森林・平原・砂漠 | terrainType + 地形修飾子 | 8種: plains/hills/mountains/forest/jungle/desert/marsh/urban |
| 資源産地 | province の deposits（goodId→基礎産出） | シナリオデータ |
| 補給拠点 | building（supply hub）＋首都 | 兵站グラフのノード |
| 国境 | 隣接関係から動的導出 | 永続化しない（導出値の原則） |
| 占領地域 | province.controller ≠ province.owner | 所有(de jure)と実効支配を分離管理 |
| 係争地域 | claims のあるプロヴィンス | diplomacy-state の claims リスト |

### 1.2 所有と支配の分離（不変条件 INV-1）

- `province.owner`（領有国）は講和・割譲でのみ変化。`province.controller`（実効支配）は占領で変化。
- 戦争中のプロヴィンスは `owner ≠ controller` を許容する。講和で解決するまで双方が正当性を主張する。
- 税収・兵員・産業出力は `controller` に従い、コア判定・正当性主張は `owner`/`cores` に従う。

### 1.3 表示モード（15モード）

政治・軍事・外交・経済・人口・資源・地形・補給・インフラ・貿易・工業力・気候・治安・同盟・戦争状況。各モードは「プロヴィンスごとの色関数＋任意のオーバレイ（矢印・ヒートマップ・ユニットカウンタ）」としてデータ駆動定義する。色は Okabe-Ito 基準のパレットを用い、色覚多様性のためパターン/アイコンを併用する（docs/11）。

## 2. 国家運営（country-system / politics-system）

### 2.1 国家の属性（初期値はシナリオデータ）

人口・国家予算・GDP・国債・税収・政治体制・国家安定度・政府支持率・組織・政党・戦争支持率・政治力・国家理念・教育水準・技術水準・社会保障・労働人口・失業率・外交的影響力・軍事力。

### 2.2 プレイヤーが操作できるレバー

| レバー | 範囲 | 即時効果 | 副作用（トレードオフ） |
| --- | --- | --- | --- |
| 税率（所得・法人・貿易関税） | 0–50% | 税収増 | 消費需要↓、支持率↓、（高税率時）資本逃避 |
| 財政支出配分 | 予算の按分 | 各部門の効果 | 赤字 → 国債発行 → 利払い増 |
| 法律（徴兵・経済・貿易・労働・教育） | データ駆動の選択肢 | 制度効果 | 政治力消費＋可決までの日数＋反対利益団体の反発 |
| 産業政策（補助金・国有化・民営化） | 建物単位 | 出力↑/コスト↑ | 予算圧迫 |
| 徴兵制度 | 5段階（志願→総動員） | 徴兵可能人口↑ | 労働人口↓、支持率↓ |

### 2.3 政治力・支持率・安定度

- 政治力（PP）: 毎日 `base × 政府効率` で蓄積。法律制定・方針ノード・外交行動に消費。
- 支持率: 生活水準・安定度・戦争の状況・税負担から毎週計算（計算根拠トレース対応）。
- 安定度（0–100）: 支持率・無秩序（プロヴィンスごとの不満）・イベントから変動。25以下で「政治危機」状態、0で革命イベントのMTTH開始。

## 3. 経済システム（economy-system / resource-system / production-system）

### 3.1 財（現代シナリオ・16種）

石油・天然ガス・石炭・鉄鉱石・鋼鉄・アルミニウム・銅・タングステン・ウラン・レアアース・食料・電力・木材・化学製品・半導体・消費財。**財リストはシナリオデータ**（1936シナリオでは半導体・レアアース・ウランを除外、歴史財を追加）。

### 3.2 産業・建物（現代シナリオ）

農場・鉱山（資源別）・発電所・製油所・製鉄所・製材所・化学工場・半導体Fab・民需工場・軍需工場・造船所・物流ハブ・建設会社・サービス/ICT（抽象セクター）。建物はプロヴィンス単位でレベルを持つ。

### 3.3 市場モデル（国家市場＋世界貿易層）

- **国家市場**: 財ごとに在庫・価格・日次の需要/供給を集計。価格は毎月末に `price = clamp(basePrice × (demand/supply)^0.5 × 平滑係数, 0.25×base, 4×base)` で更新（判断 D-008: 月次更新と在庫バッファで計算量を制御）。
- **貿易**: 国間の取引は「輸出余剰のある国 ↔ 輸入不足の国」を価格差でマッチング。輸送能力は（Phase 3では貿易協定の有無＋関係値、Phase 4で輸送船と港の容量を導入）。
- **制限**: 経済制裁・禁輸は国ペアの取引を遮断。戦争国間は自動遮断。
- **貨幣の保存則（INV-2）**: 全取引は売り手と買い手の間の資金移転であり、世界の総資金量は不変。国庫・家計・産業の帳簿は統合検証可能にする（property test の対象）。
- **GDP**: 各建物の付加価値（産出額 − 投入額）の合計＋サービス部門の付加価値。月末に集計。

### 3.4 ショックの伝播

資源不足は下流産業の稼働率を落とし（投入が不足 → activeRatio低下）、失業と消費財不足を生む。インフレは消費財価格指数として観測され、生活水準を通じて支持率へ波及。施設破壊（爆撃・占領）は建物レベルを損傷させ、復旧に建設能力と資源を要する。

## 4. 軍事システム（military-system / combat-system）

### 4.1 階層と編成（段階導入）

| フェーズ | 内容 |
| --- | --- |
| Phase 1 | 師団（単一ユニット）。人力・装備プールから訓練 |
| Phase 2 | 師団テンプレート（大隊構成を設計）、軍団/軍集団による集約、戦線、攻勢計画、指揮官 |
| Phase 3 | 旅団アタッチメント、動員（徴兵制度と連動）、戦闘経験 |

### 4.2 師団の状態

人力・装備（財の実装: 歩兵装備・火砲等、シナリオ定義）・組織率(org, 0–100)・強度(strength, 0–1)・士気（org回復速度の修飾）・経験（0–5段階）・補給効率・指揮官。

### 4.3 戦闘解決（プロヴィンス単位バトル）

- 1プロヴィンスに1バトル。攻撃側・防衛側とも前面幅（terrain別: plains 10 / hills 6 / mountains 4 / urban 5）まで師団が同時参戦、残りは予備。
- 日次解決: 攻防の火力比 × 地形 × 天候 × 補給効率 × 指揮官スキル × 航空支援(Phase 4) × 士気 → org/人力/装備の損耗。決定論ロール（PCG32）でランダム性を注入。
- 撤退: org < 20% で強制撤退（味方支配の隣接プロヴィンスへ）。包囲（補給途絶）では org 回復不能＋日次崩壊損耗 → 一定期間後に降伏。
- 占領: 防衛軍不在の攻撃側支配で14日（設定可能）経過後 `controller` が移転。

### 4.4 過剰マイクロマネジメント回避（戦線指示）

- **戦線(Front)**: 指定した国境区間（プロヴィンス集合）への師団割当単位。プレイヤーは戦線に「防衛」「攻勢（目標軸指定）」「撤退」のスタンスを出すのみ。
- 師団の個別移動命令も可能だが、戦線割当がある師団は戦線AIが再配置する（優先度: 明示命令 > 戦線AI）。
- 攻勢計画は「目標プロヴィンス群＋投入上限」を宣言する形。個々の移動経路はエンジンが計算する。

## 5. 兵站・補給システム（logistics-system）

### 5.1 モデル（MVP: グラフ到達性＋距離減衰）

- **ノード**: 首都・補給ハブ建物・港湾（海上輸送線が首都圏に接続する場合）。**ソース**: 首都（必要資源の集約点）。
- **グラフ**: プロヴィンス隣接グラフ、エッジ重みは `1 / infraLevel`（infra 0–5）。鉄道（Phase 2）は重みをさらに低下させる専用エッジ。
- **到達性**: ソースから Dijkstra で各プロヴィンスまでの最短コストを計算（戦線ごとに週次・損壊イベント時に再計算）。
- **供給効率**: `supplyEff = clamp(capacityFactor × distanceFactor, 0, 1)`。`distanceFactor = max(0, 1 − dist/radius)`、`capacityFactor = ハブ容量 / 要求量`。
- **効果**: org回復速度 `×(0.2+0.8s)`、戦闘力 `×(1−0.5(1−s))`、`s<0.5` で装備損耗・士気低下、移動速度 `×(0.5+0.5s)`。
- **拡張（Phase 3+）**: 輸送容量・優先度つきフロー（最大流量問題）へ置換。燃料・弾薬・食料・装備補充を個別財として輸送量に反映。

### 5.2 補給網の攻防

- ハブ・鉄道・港湾は占領・破壊の対象。遮断された軍集団は包囲状態になり崩壊するまでの時間が戦略的猶予として可視化される（地図「補給」モードでボトルネック表示）。

## 6. 外交システム（diplomacy-system）

### 6.1 関係値の構成（好感度単独ではない）

`relation = baseline + 意思距離 × w1 − 脅威認知 × w2 + 経済相互依存 × w3 + 共通脅威 × w4 + 履歴イベント × w5 − 領土紛争 × w6`

- 脅威認知は影響力マップ（相手の軍事力の自国国境への近接度）から計算。
- 経済相互依存は貿易額/GDP 比。
- 履歴イベント（戦争・保障・制裁）は減衰するエントリ。

### 6.2 行動リスト

不可侵条約・軍事同盟・経済同盟・貿易協定・軍事通行権・独立保障・経済制裁・禁輸・共同研究・宣戦布告（開戦理由CBを要する）・停戦・講和・領土割譲・傀儡化・独立承認・国際機関（シナリオ定義の機関、Phase 4）。

### 6.3 宣戦と講和

- 宣戦にはCB（領土回復・保護・解放等）が必要。CBなしの宣戦は安定度・外交的影響力・支持率へ大幅ペナルティ。
- 停戦は戦線固定での自動提案、講和は戦争貢献度スコアによる要求配分（講和会議は Phase 4 のUI機能。MVPは「現状ラインでの白紙講和＋割譲要求」のみ）。

## 7. 技術研究（research-system）

- 技術ツリーはシナリオデータ（JSON）。13カテゴリ: 歩兵・陸軍兵器・装甲・航空・海軍・通信・工業・エネルギー・医療・農業・情報・宇宙・サイバー。
- 各技術: 前提技術・研究費用・研究期間（研究力依存で変動）・時代制約（シナリオ年により出現）・効果（修飾子 or 解禁）。
- 研究力（RP）: 教育予算 × 大学建物 × 識字率。並行研究枠 2（MVP）。完了した技術は国の修飾子マップに適用される。

## 8. 国家方針・政策（politics-system の focus サブシステム）

- 方針ツリーはシナリオ/国家データ駆動（工業化・民主化・軍備拡張・経済改革・科学技術振興・外交重視・福祉国家・エネルギー自立・地域統合・中立政策）。
- **固定一本道ではなく条件ゲート**: ノード出現条件（年・政体・安定度・既得ノード・戦争状態）をデータで定義。同じ国でも状況で利用可能ノードが変わる。
- 効果は修飾子・解禁・イベント起動。取得にPP＋所要日数。分岐は排他の場合もデータで宣言（`exclusiveGroup`）。

## 9. 人口・社会（population-system）

- **地域集約モデル**（個人シミュは行わない）。プロヴィンスごとに: 総人口・年齢構成（0–14/15–64/65+）・識字率・就業（産業別・失業）・平均所得・生活水準(0–1)・満足度・成長率・徴兵可能人口。
- **成長**: 出生率＝シナリオ基準 × 生活水準修飾、死亡率＝シナリオ基準 × （医療技術・飢饉・戦争）修飾。月次更新。
- **移動**: プロヴィンス間の純流入 = f(賃金差, 生活水準差, 距離, 治安)。戦域からの流出は難民として隣接安全地域へ（Phase 3）。
- **徴兵可能人口**: 15–64歳人口 × 徴兵制度率 × (1 − 既就業軍産業分)。

## 10. イベント（event-system）

- データ駆動: `{id, trigger(条件DSL), mtth(平均発生間隔) or onCondition, options[{text, effects, aiWeight}]}`。
- effects はコマンド列として定義（決定論・リプレイ対応）。選択肢は国家状況でAI重みが変わる。
- チュートリアルもイベント機構で実装する（仕様の一部）。

## 11. ゲームAI（ai-system）

- 責務分離: 国家戦略・経済・外交・軍事戦略・戦術・生産・研究・建設・危機対応の9モジュール。各モジュールは週次の思考サイクルを持ち、国家インデックスで時間分散（同tick集中を避ける）。
- 手法: **Utility AI**（戦略・経済・外交の意思決定）、**ルール＋ビヘイビアツリー**（戦術手順）、**影響力マップ**（脅威認知・戦線評価）。HTN/GOAP/MCTSは評価の結果、コスト対効果で不採用（判断 D-009、docs/09）。
- 難易度: ①評価頻度 ②計画の深さ（先行ターン数）③誤差注入確率 の3つを主軸とし、資源ボーナスは Hard 以上で最大±10%に制限して透明化する。
- **判断記録**: 各AI判断は「選択肢・スコア・理由」をリングバッファに記録。開発者モードで閲覧可能。
- LLM: ランタイムには使用しない。MODビルド時のイベント文章下書き生成（補助ツール）のみ検討する。

## 13. 学習と進行のカーブ

- プレイヤーはまず「地図・時間・1軍事行動」だけの最小UIで開始（Phase 1）。
- システム解放: 軍事 → 経済/建設 → 貿易/研究 → 外交高度化 → 海空軍。解放は設定で全開にすることも可能。
- ツールチップは常に計算根拠を示し、「なぜこの数値か」を学習させる。チュートリアルはイベント機構で段階的に出す。
