# Design

## Context
決定論は本プロジェクトのピラー5であり、JS環境特有の問題（Math.random不可・超越関数の実装依存・IndexedDBクォータ）が既知の制約（docs/09 §3、MDN確認済み）。エンジンはWeb Workerで動くが、本ChangeではNode上で同一コードを直接実行してテストしやすくする。

## Goals / Non-Goals
- Goals: 同一シード＋同一コマンド列の完全再現・月末ハッシュアンカー・tick処理の決定論的順序
- Non-Goals: UI連携（Change 7）、Worker起動（Change 2以降で利用）、セーブ（Change 6）

## Decisions
- **D-011（数値規約）**: 整数（money/pop）＋float64仕様確定演算のみ。BigIntは不採用（MDNのJSON/演算制約）。超越関数はLUT＋線形補間で置換。
- **乱数**: PCG32を自前実装（依存ゼロ）。子ストリームは `hash(worldSeed, systemName, scope)` から派生。システム名は文字列固定表（レジストリ登録順=ID）で決定論的に解決する。
- **反復順序**: 全ループID昇順。Map/Setはソート後に使用する規律をESLintカスタムルール＋レビューで担保。
- **月次境界**: `tick % 30 == 0`。シナリオが「30日月」宣言を持つことを仕様として許可（既定は30）。
- **アンカー**: 月末にFNV-1aベースの状態ハッシュ（主要ストアの逐次ハッシュ）を記録し、ジャーナルに付随させる。

## Risks / Trade-offs
- LUT補間は精度を落とすが、戦略ゲームの用途では許容。精度が要る箇所は整数論理に置換する。
- ESLint規律だけでは決定論違反を完全には防げないため、CIのリプレイ二重実行テストを最後の砦にする。
