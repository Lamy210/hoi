# 軍集団・軍の作戦指揮センター（UI first）

## 目的
既存のArmyGroup→Army→Divisionの階層、指揮官配属、手動命令、Front AIを再利用し、HOI4のように軍集団から一括で現在戦力を確認し命令できる入口を作る。

## 新しいUI
- 軍集団/軍ボタンを選択すると単一の作戦指揮パネルが表示される
- 指揮官・技能、所属師団数、要注意師団、平均組織率、平均補給、交戦/移動、戦線所属、手動固定、3財不足を集計
- 指揮系統の所属を **Unit.armyId → Army.groupId** から都度派生。重複保存しない
- 「全師団を選択」で既存地図フォーカス・複数師団命令を再利用
- 「自動作戦を保留/再開」は既存 setManualHold に送信、手動命令を上書きしない
- 戦争中の当該国家の戦線だけを選択し「全師団を割当」で assignToFront を再利用
- 「戦線割当を解除」は unassignFromFront に送信
- 戦線がないときは割当ボタンを無効化し既存の戦線画面へ誘導
- フロントの所属数はスナップショットに基づく生存師団のみ

## 安全性
- 現行 Command registry が所有権・戦争状態・件数上限・重複IDを最終検証
- 送信中の重複命令を防止。1軍集団5軍×24師団=120で既存1命令256師団制限内
- 空の軍/軍集団は参照・集計のみ、命令を発行しない
- シミュレーション状態/セーブスキーマは変更しない（v18互換）
- 軍集団司令官の戦闘補正は **未実装** であることを明記し、誤ったUI表現を避ける

## 受入条件
- 軍集団の所属師団が移籍・除隊に応じて動的に更新される
- 複数師団の戦力・補給不足・戦闘/移動状況が投影値と一致する
- 戦線未作成時の割当ボタンは使用不可
- 自動保留/再開が所属師団すべてに適用され、他国師団に影響しない
- 保存/復元後の編成メンバーが同一、決定論的12 tick が同じ
- TypeScript/Vitest/Playwright/OpenSpecを維持

## 後続
軍集団単位の作戦計画エンティティと戦線の配分、軍集団司令官補正、作戦線の描画・編集、HQ/戦域は別PRで実装する。
