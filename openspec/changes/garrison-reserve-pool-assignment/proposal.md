# 駐屯作戦の予備師団を含めた配置最適化

## 背景
PR #95で選択済みの最大4師団・4防衛対象に対する総移動日数の最小化を導入した。ただし、初回の貪欲法で選ばれなかった予備師団を後段の最適化に含めないため、より短時間で到達できる未選択師団が残る場合がある。

## 変更内容
- 既存の防衛優先順位（敵境界、敵師団数、首都、登録港容量など）と、移動先を決める第一段階のルールは維持する。
- 第一段階で決まった最大4防衛地点に対し、選択済みの師団に加え、同じ駐屯作戦に配属された未使用の安全な予備師団を最大8個まで補充する。
- 予備候補は、プレイヤーの手動固定、移動中、包囲中、戦闘中、前線配属、破壊済み、敵支配地の師団を除外する。
- **元の駐屯目標のいずれかに現在配置されている師団は、たとえ複数存在していても追加予備候補に含めない。** 既存の守備隊の引き抜きは初期プランナーだけが行う。
- 予備候補の予備選択は現在のマップ上の最小二乗距離で安定ソートし、上位8個までとする。この距離は経路の合法性や移動日数を意味せず、実際の割当には従来の合法陸路探索と師団固有の区間移動日数を用いる。
- 選ばれた師団4個＋追加予備8個の最大12候補から、最大4防衛地点に対して重複なしの割当を全探索し、総予想移動日数が既存プランより厳密に短い場合のみ採用する。
- 追加経路探索は最大4×(4−1)＋4×8=44回、割当探索は最大12P4=11,880通りで、週次4命令の上限は変更しない。

## 安全性・非機能
- 変更対象は読み取り専用プランナー。セーブスキーマ・駐屯命令・ゲームエンジンの公開コマンドは変更しない。
- 選択済みの防衛対象集合と順序は変更しない。既存守備隊の保持、手動固定、移動不可の条件を緩和しない。
- すべての追加割当は `findPath(...,false)` で非敵対陸路の合法性を判定し、経路がなければ候補から除外する。
- 予想移動日数は現時点の補給・天候・師団速度に基づく値で、将来の到着日は保証しない。
- **全候補師団・全目標のグローバル最適ではない。** 追加候補を最大8個に制限し、地理的近似で絞り込むため、除外された遠方師団が最適である可能性は残る。
- 今回は実運用負荷の計測を行わないため、規模が大きいシナリオでの性能・スループットは別途PoCで検証する。

## 代替案
- 256師団×64目標の全探索：経路探索数と割当探索量が増え、エンジン更新時の負荷が大きく不採用。
- 選択済み師団だけの最適化を維持：改善余地が残るため不採用。
- 最大8予備候補を含む有界全探索：性能・再現性・安全性を両立できる範囲として採用。

## ロールバック
この変更は `garrisonBatchOptimization.ts` と `garrisons.ts` の計画段階のみ。問題があれば予備候補の引数を渡す処理を外すことでPR #95の挙動へ戻せる。
