# 複数師団の型番別装備の一括交換

## 目的
既存の単一師団型番交換を軍団/複数選択へ拡張し、HOI4型の軍備更新を効率化する。

## 安全性・決定論
- コマンド `exchangeUnitsEquipment` を追加。引数は `unitIds[]`、`fromModelId`（未分類可）、`toModelId`、`quantity`（各師団あたりの整数）。
- 対象は **2〜100師団**、IDの重複禁止。IDを昇順に正規化して処理順を固定。
- 個別の所有権、対象州の支配、移動/戦闘/包囲、型番/財種一致、各師団の交換元数量をすべて事前確認。
- 国家倉庫の新型装備在庫は **各師団の要求数の合計** で検証する（単体ごとの在庫検査だけでは不十分）。
- コマンド検証段階ではいずれの倉庫・師団在庫も変更しない。
- 実行時は二財在庫配列・型番国家倉庫・師団別支給記録を**複製して更新し、すべて成功したときだけ一括コミット**。途中でエラーが起きても原本は変更されない。
- 個々の師団と国家倉庫の二財総装備数は変更せず、型番の所在情報を1対1で交換する。型番別戦闘力は既存の装備計算から派生。
- 型番別在庫は当該財種の集約在庫の内訳。旧セーブ・v18セーブ形式はそのまま利用する。
- UIで複数師団選択、交換元モデル/未分類、交換先モデル、各師団の数量を指定し、必要総数と最小交換元保有数を表示。
- 対象の一部が不適格・在庫不足・モデルが未指定の場合、送信ボタンを無効化。サーバ側（engine command）でも再検証する。

## 検証
- 倉庫在庫190に対する2師団×100の注文は全部拒否。200なら両師団へ同量支給。
- 旧型返却と新型受領の型番別記録が一致。総装備数が増減しない。
- ID重複・100師団超過・敵国部隊・移動/戦闘/包囲・不正数・型番未保有の拒否。
- 異なるID指定順でも結果ハッシュ一致。v18セーブ/ロード後20日一致。
- Playwrightの2師団選択、在庫不足時の一括交換無効化と既存単独コマンド保持。
- TypeScript/Vitest/Playwright/OpenSpecの全CI成功。
