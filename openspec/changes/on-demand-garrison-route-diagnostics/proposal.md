# 駐屯作戦のオンデマンド陸路到達診断

## Why
PR #90で防衛・移動・未防衛・敵占領の状況を可視化できるようになったが、経路探索の結果がUIにないため「陸路がない」のか「担当師団が移動不可」なのかを判断できない。

## What Changes
- 作戦単位の読み取り専用 `diagnoseGarrisonRoutes` をエンジンに実装する。
- 駐屯AIと同じ非敵対陸路探索 `findPath(..., false)`、所有権・戦闘・包囲・手動固定・移動・最後の守備隊保護を用いて、各地点の状態を分類する。
- 指揮バーの各駐屯作戦に「陸路を診断」ボタンを追加。明示操作時にだけWorkerへRPCを送信し、診断結果を表示する。
- `tick` と `revision` が現行スナップショットと一致しない古い診断結果は表示しない。
- 1回の診断で経路探索は最大64回とし、上限到達時は「未確認」と表示。未探索を到達不能と誤認させない。

## Capabilities
- 現地守備、移動中、支配喪失、停止中、配属可能師団なし、候補師団からの陸路あり、現在の条件では陸路なし、上限による未確認を識別する。
- 「陸路あり」は個別の合法ルートの存在のみを意味し、複数地点への同時配置を保証しない。
- `WorldState`、駐屯作戦定義、保存データ、命令キューを変更しない。

## Impact
- エンジン: `src/engine/military/garrisonRouteDiagnostics.ts`
- Worker/RPC: `src/engine/worker.ts` と `src/ui/engineClient.ts`
- UI: `src/ui/ArmyCommandDock.tsx`
- Vitest/Playwrightによる診断と非変更性、検証上限、操作経路の回帰。
- 常時スナップショット生成に経路探索を追加しない。

## Risks / Rollback
- 大規模な駐屯作戦では経路探索が負荷となるためユーザー操作時だけ実施し、64回で停止する。
- 戦闘・支配権・通行権の変化後は過去の診断が古くなる。再診断が必要。
- 問題があればRPCと診断ボタンを戻せる。既存の作戦・保存形式に依存する変更なし。
