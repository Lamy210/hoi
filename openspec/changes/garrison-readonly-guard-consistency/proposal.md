# 駐屯の読み取り専用診断を現地守備条件に統一

## Why
PR #99で駐屯計画と移動命令の実行時検証は、増援が実際に到着するまで最後の現地守備師団を移動対象にしないよう修正された。しかし陸路診断とUIカバレッジの未防衛理由には、到着予定の師団も「現地守備の2個目」として数える旧条件が残った。AIが動かせない最後の守備隊を、診断が到達候補として表示するため、運用判断を誤る。

## What Changes
- 明示操作で実行する `diagnoseGarrisonRoutes` において、駐屯目標に実際に停止している生存配属師団の人数を使って候補を選ぶ。移動中の増援は候補師団の出発可否を緩めない。
- 陸路診断の「現地防衛中」「移動中」表示は維持する。既存の経路探索上限64件、推計日数・防衛優先順位・読み取り専用の制約も変更しない。
- スナップショット専用の `projectGarrisonCoverage` も現地で停止中の守備人数だけで出発可能性を判定する。移動中の増援は将来の到着状況として表示を維持する。
- 統合・単体テストで、増援到着前は出発候補ゼロ、実際の到着後は移動候補ありの状態遷移を検証する。

## Capabilities
- 駐屯指揮UIの診断に、実際のプランナーと矛盾する移動可能表示を出さない。
- 未来の到着予定と現地に残る実守備隊を区別して可視化する。

## Impact
- 対象: `src/engine/military/garrisonRouteDiagnostics.ts`、`src/ui/garrisonCoverage.ts`、対応するVitest、OpenSpec strict CI。
- 非変更: 駐屯作戦の永続状態、移動命令、実際の駐屯計画、シミュレーション、セーブ形式、UI公開操作。
- 限界: 診断は依然として最初に到達可能な候補を示す参考情報であり、最大4命令の同時割当や将来の到着日は保証しない。
- 障害モード: 増援が移動途中の間、これまで「移動可能」とされた箇所が「移動可能な師団なし」に変わる。実行不能な移動の偽陽性を抑制する意図的な表示変更。
- 代替案: (1) ドキュメントの注意書きのみ追加：偽陽性が残るため不採用。(2) 画面で移動計画を直接実行：非同期Workerの読み取り専用境界と負荷に影響するため不採用。(3) 診断と表示だけ現地守備人数基準に合わせる：最小・低リスクなので採用。
