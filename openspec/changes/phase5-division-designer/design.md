# Phase 5B 設計

## 所有関係とモデル
- BattalionDef: id, category, manpower, equipment[{goodId,qty}], days, width, attack, defense, org, speed, supply。定義はpackに固定し、バージョンで識別。整数数量・非負有限値・既知財/技術を検証。
- TemplateRevision: country, templateId, revision, name, battalionIds[], supportIds[]。同じIDの編集はrevisionを増やす。使用中の版は削除不可。大隊1〜25、支援0〜5、同種支援の重複不可。国ごと最大128テンプレート、256保持版。超過は拒否。
- UIは算出値をリクエストし、Worker内の純粋関数で再算出。送信するのはIDと構成のみ。人力・装備必要量は和、戦闘幅は和、組織率は人力加重平均、速度は戦闘大隊の最小、補給需要は和。定義のない能力は表示しない。数値の確定はバランス検証後。
- 旧固定3編成は組み込みテンプレート版として保持。v4の既存師団は旧定義から復元。v5の訓練は予約済み量・完了日を保持。変換後の資源総量は不変。

## 状態機械
draft → queued → training → ready → deployed。queuedで必要資源を確認。人力と装備を全量予約してからtrainingへ。trainingは日次進行、完了時ready。readyは手動配備または自動配備設定。queued/training/readyの中止は予約量を一度だけ返却、消滅国家は失効として台帳記録。配備州喪失はready時に配備拒否し、自国支配の別州を指定可能。訓練枠は現行20件を維持。
- 新規編成・改訂、募集、取消、配備、配備州変更は所有権・tick境界で検証。
- 既存師団変更は戦闘中/移動中は拒否。差分資源が揃った場合のみ原子的に適用、余剰は返却、訓練/組織率ペナルティを記録。変更前の損耗が無料で回復しない。基本式: 現在保有は新上限以下に切り詰め、不足分を購入/予約可能な範囲で追加する。正確な再編コストは実装前のテスト表で固定。
- 配備済みの旧版は自動更新しない。テンプレート更新の確認ダイアログと差分表示を用意。
- AIも同じ募集・配備コマンド。旧createUnitはデバッグ/移行用途に限定し、通常プレイヤー・AIから拒否する。

## 実行順・安全
コマンド→既存戦闘/補充→生産→訓練予約/進行→経済集計→週次AI。補充優先はphase6変更まで固定。予約在庫は自由備蓄に含めない。資源保存: 開始時自由在庫 − 予約 = 終了時自由在庫、取消は逆、配備は予約→部隊。負値・二重返却は拒否。
- 戦闘幅は参加大隊幅の合計を地形容量に対して割当。既存「地形幅=師団数」の単位を変更するため旧戦闘結果の完全一致は保証しない。旧標準師団の相対収容幅は実測で調整。組織率・速度・供給は同じ算出関数から取得。
- 保存: 次のschema版に移行チェーンを用意。旧版を旧アルゴリズムで検証後に移行し、新版で再検証。版付き参照、予約、進行、ID countersをハッシュ対象とする。未対応版は拒否。
- UI: 編成編集→募集→訓練進捗→配備/中止→地図上部隊→戦線割当。JA/EN、キーボード、停止中の命令表示、失敗理由。
- 性能: 旧ティアS・Mを再測定し、テンプレート算出は版別キャッシュ。世界規模で毎日全テンプレート再計算しない。数値保証なし。
