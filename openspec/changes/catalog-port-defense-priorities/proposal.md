# 登録済み港湾カタログの駐屯優先順位への連携

## Why
PR #92〜#93で駐屯AIが首都・敵師団集中度・沿岸を考慮できるようになったが、沿岸は実在する港と同義ではない。Phase8Aの検証済み港湾カタログを作戦判定へ安全に連携する。

## What changes
- シナリオパックの `maritime.ports` を `portCapacitiesFromPack` で州番号ごとの静的収容力配列へ投影する。既存の `projectMaritimeCatalog` で州IDの整合を検証する。
- `WorldState.runtime.portCapacities` はセーブ対象外の派生キャッシュであり、初期生成と既存セーブ復元の両方で同一パックから再計算する。カタログ不在時は全州ゼロ。
- 駐屯優先度を「交戦中の敵境界の有無 → 隣接敵師団数 → 敵隣接数 → 首都 → 登録港の収容力 → 沿岸 → インフラ → 人口 → 州ID」とする。
- 陸路診断の根拠と収容力表示を追加する。収容力はシナリオ設定に基づく優先度の指標に限り、物理的な補給能力・輸送枠・海軍航行を付与しない。
- `garrisons` の移動命令・手動固定・最後の守備師団保護・毎週最大4件の制約を変更しない。

## Alternatives
- 既存の沿岸フラグを「港」とみなす: 誤判定のため不採用。
- セーブへ港湾容量を保存する: 静的パック由来であり冗長なため不採用。スキーマ移行と旧データの扱いも複雑になる。
- 全コンポーネントへPackを引き回す: 既存コードへの変更が大きいため不採用。
- runtime派生値: WorldStateに紐づき、同一パックから復元できるため採用。

## Risks and limitations
- 港カタログの異なるパックでのセーブロードは既存 `packFingerprint` の不一致で拒否される。港の収容力変化で旧エンジンと同一の将来ハッシュになることは保証しない。
- `runtime` 内の情報は保存されず、その内容自体をhashWorldへ含めない。初期ロード/復元以外で外部から変更しない。
- 港への防衛配置は陸路のみ。海を越えた駐屯や補給輸送は非目標。
- 脅威度、補給状態、港容量の重みを利用した実運用の負荷・バランスは後続PoCで検証する。
