# Combat system — garrison last-guard validation at command application (delta)

## ADDED Requirements

### Requirement: 駐屯命令の適用時にも最後の守備隊を保護する
駐屯AIが発行した移動命令は、実際のコマンド適用時に移動元の最後の守備隊かどうかを再検証しなければならない（SHALL）。移動元が自国支配の駐屯目標であり、他の配属師団による現地守備がない場合、その命令を拒否しなければならない（SHALL）。拒否時は師団の位置・経路を変更してはならない（SHALL NOT）。

#### Scenario: 最後の1師団を直接移動させるAI命令
- **WHEN** 自国駐屯目標を守る配属師団が1個だけで、別の指定目標へのAI移動命令が適用される
- **THEN** 命令は`staleGarrisonOrder`で拒否され、師団はその地点を守り続ける

#### Scenario: 2師団から1師団になる
- **WHEN** 同一目標を守る2師団に対して移動命令が連続して適用される
- **THEN** 最初の命令で1師団が出発しても、残った最後の1師団への後続移動命令を拒否する

#### Scenario: 守備地点ではない移動元
- **WHEN** 師団が駐屯目標以外の自国支配州にいる
- **THEN** 他の検証条件と合法陸路が満たされれば既存どおり移動を許可する

### Requirement: 計画と適用の整合
駐屯AIの計画処理、追加予備師団の最適化、既存コマンド契約とセーブスキーマは変更してはならない（SHALL NOT）。最後の守備隊の判定は作戦に所属する生存師団と、現在地または移動先から決定論的に算出しなければならない（SHALL）。

#### Scenario: 到着予定は現地守備ではない
- **WHEN** 他の配属師団が到着予定であっても、まだ駐屯目標に到着していない
- **THEN** 現地に残る最後の師団の移動命令を拒否する

#### Scenario: 計画後に守備状況が変わる
- **WHEN** 計画後に別の守備隊が移動して、実行時に最後の1師団だけが残る
- **THEN** コマンド適用時に残存守備隊を再判定して命令を拒否する
