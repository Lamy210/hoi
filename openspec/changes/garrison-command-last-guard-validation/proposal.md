# 駐屯AIコマンド適用時の最後の守備隊保護

## Why
駐屯AIの`planGarrisonMoves`は防衛対象に残る最後の守備隊を移動させないが、実際の`garrisonMove`コマンド検証は作戦所有権・師団状態・経路の合法性だけを再確認し、移動元の守備隊数を検証しない。計画後からコマンド適用までに、別の師団が出発・撃破・経路変更した場合、駐屯対象が空になる命令を通し得る。

## What Changes
- `isLastGarrisonGuard`を導入し、移動元が自国支配の駐屯目標である場合、配属中の他の生存師団が現地守備中またはその地点へ移動中か判定する。
- `garrisonMove`コマンド検証時に同じ判定を再実行し、最後の守備隊を移動させる命令を`staleGarrisonOrder`で却下する。
- 移動元が駐屯目標ではない、または他に防衛中・到着予定の師団がいる場合、既存の命令検証と合法な経路探索を引き続き使用する。
- 既存の駐屯計画、最短移動時間最適化、優先順位、セーブ形式、命令の公開引数は変更しない。

## Capabilities
- 計画での守備保護に加えて、実際のAIコマンド適用時にも守備隊を保護する。
- 同じ移動元から複数のAI移動命令が連続して適用される場合も、残り1師団となった時点で後続の移動を拒否する。
- コマンドを拒否した場合は師団の位置と移動経路を変更しない。

## Impact
- 対象: `src/engine/military/garrisons.ts`, `src/engine/commands.ts`, `tests/integration/area-garrison-defense.test.ts`
- パフォーマンス: 駐屯移動命令の適用時に作戦配属師団を探索（最大256件）。通常のUI描画・毎日更新ごとの追加処理なし。
- 互換性: 新しい状態・セーブフィールド・コマンド種別を導入しない。今まで不正に通過し得たAI命令は拒否され、旧ビルドと完全に同じ将来リプレイは保証しない。
- リスク: 到着予定の守備隊を現在の防衛人数に含めるという既存`planGarrisonMoves`の判定を維持。到着失敗・通行権変更への将来的な対策は別途検討。
- Rollback: `garrisonMove`検証の守備隊判定を撤回すれば旧挙動に戻るが、安全性の後退となるため推奨しない。
