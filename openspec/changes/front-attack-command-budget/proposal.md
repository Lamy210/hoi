# 戦線AI攻勢キューの投入上限と手動命令優先を修正

## Why
攻勢モードで戦力比の計算に用いる師団条件と、命令を送る師団条件が一致していなかった。手動固定中・戦闘中の師団を攻勢命令の対象に数えると、検証で却下される命令が投入上限 (Front.cap) と週次4命令枠を占有し、後続の有効師団に命令が届かない。重複命令の抑止で発行が失敗しても、同様に枠とログが消費される。

## Scope
- `runFront` の攻勢段階では、手動固定・進軍中・包囲・実戦闘中・組織率0の師団を発行対象から除く。
- `cmd` が「実際にfrontMoveをキューに追加したか」を返し、攻勢・集結・防衛・後退の命令数と成功ログに反映する。
- 戦線の戦闘力評価・命令発行ルール・保存形式を変更しない。発行後に手動命令や戦線revisionが変更された場合、既存の`frontMove`検証で拒否する。
- 処理順は既存の師団列を保ち、同じゲーム状態から同じ命令列を生成する。

## Risk / rollback
軍需バランスそのものの変更ではないが、今まで枠が誤って失われていた状況で有効な攻勢が増える。AI行動の差分を短期/長期リプレイで計測する。問題があれば本変更のコードとテストのコミットをrevertし、セーブ形式は維持する。
