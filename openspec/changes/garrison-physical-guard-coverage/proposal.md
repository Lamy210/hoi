# 駐屯の現地守備隊と到着予定増援の区別

## Why
従来の `planGarrisonMoves` は、現在地にいる師団と、その州を経路終点とする移動中師団を同じカバレッジとして数えていた。PR #98でコマンド適用時に最後の守備隊の再検証を追加したが、到着予定師団を「現地守備済み」とみなす判定を引き継いでいるため、増援到着前に最後の現地守備隊が出発してしまう。

## What Changes
- 既存の目標カバレッジ（移動中師団の到着予定も含む）と区別して、実際にその州に滞在し、未移動の配属師団のみを `stationed` として計算する。
- 既存のプランナーは、すでに到着予定のある州を新規配備候補にしない方針は維持する。ただし駐屯目標から師団を引き抜く場合は、**その場に別の現地守備師団がいること**を条件とする。
- `garrisonMove`の最終検証にも同じ「現地に残る師団」条件を適用する。増援到着前には拒否し、到着後に実際の2師団を確認した場合は1師団の出発を許可する。
- PR #98のChange文書の該当箇所も現在の仕様へ修正し、仕様と実装の不一致を残さない。

## Capabilities
- 現地に残る最後の配属師団を、到着予定師団を理由に先行出発させない。
- 増援の到着後には既存の週次防衛再配置を再開できる。
- 複数守備隊がいる場合は1師団を移動しても守備人数が残るよう計算する。

## Impact
- 対象: `src/engine/military/garrisons.ts` および統合テスト、OpenSpec。
- 非変更: 駐屯作戦・命令形式・シミュレーション保存スキーマ・優先度・最適化済みの行き先選択・その他の軍団や戦線。
- デグレリスク: 増援到着前の防衛再配置が以前より遅れる。毎週の計画時に現在の配置を再評価するため、必要なら到着後に進軍する。
- 性能: 目標数と配属師団数に比例する小さな追加カウント。未測定の性能保証はしない。
- ロールバック: 現地人数に関する変更を撤回すると、到着前の無防備期間が再発し得る。
