# 駐屯作戦の小規模バッチ割当最適化

## Why
従来の駐屯AIは重要度の高い州から順番に師団を選び、候補の比較には通過州数を用いる。同じ週に複数地点へ移動する場合、高優先州へ最も近い師団を先に割り当てることで、他の師団が大きく迂回し、合計移動時間が長くなる。

## What Changes
- 駐屯命令の候補選択を経路の州数ではなく、同じ移動処理の `segmentDays(w,from,to,unit)` で算出する予想日数によって比較する。
- 既存の優先順位と条件で確定した最大4件の移動命令を入力とし、**選択済み師団と防衛地点を固定したまま**行き先の組み合わせを全列挙（最大4! = 24通り）して総予想移動日数を最小化する。
- 代替経路は既存の `findPath(w,from,to,owner,false)` で再検証し、経路がない組み合わせは候補から外す。代替経路探索は最大12件。
- 同じ移動日数の組み合わせでは元の割当を維持し、**厳密に短縮できる場合のみ**変更する。
- 初回プランナーが守備する高優先地点、使用する師団、出発地点、最後の守備隊の保護、手動命令・戦闘・包囲・移動中の除外、週次命令上限は一切変えない。

## Alternatives
- すべての師団・全防衛地点での最小費用フロー: 256師団・64地点の最悪探索負荷と守備起点の容量制約が重いため今回不採用。
- 2地点ごとの交換のみ: 局所最適に陥るため不採用。
- 候補経路長の短さだけで選択: 補給・天候・装備による移動日数を無視するため不採用。
- 週4件の選択済みバッチに限定した厳密割当: 経路探索・組合せ数の上限を保証できるため採用。

## Non-functional / Risks
- 既存の駐屯作戦・WorldState・セーブ形式・コマンド契約は変更しない。異なるビルド間で移動結果・将来ハッシュが変わる可能性はある。
- 評価するのは現在の天候・補給・装備を反映した区間所要時間の推定値であり、実際の到着日時を保証しない。世界状態は毎日変化する。
- **選択済み師団と地点だけの厳密最適化**であり、予備師団全体・防衛対象全体に対するグローバル最適は保証しない。
- 入力を変更しない読み取り専用のプランナーとして実装。経路がない組合せ、無効なルート、改善がない場合は旧割当を保持する。

## Verification

- 最後の守備隊・手動固定・週次上限・シミュレーションのセーブ復元後14tickの一致を検証。
- TypeScript型検査・Vitest・ビルド・Playwright・OpenSpec strictに成功してからマージ。
