# 駐屯計画内の重複陸路探索を削減

## Why
駐屯計画は最大64防衛地点と256配属師団について合法陸路を調査する。現在は同じ州にいる複数師団が同じ目標へ向かう場合でも、師団ごとに `findPath` を呼び出す。さらに初回の候補選定と最大12師団の割当最適化で同じ州・目的地の探索を繰り返している。

## What Changes
- `createGarrisonRouteLookup` を追加し、**単一の駐屯計画呼び出しの間だけ** `from` と `to` をキーに合法陸路検索結果（到達不能のnullも含む）を保持する。
- 初回候補選定と後段の `optimizeGarrisonBatch` が同じlookupを共有する。割当最適化だけを直接呼び出す場合も、その関数の実行中だけキャッシュを作る。
- キャッシュに保持するのは通行合法性と地理的ルートのみ。移動日数は師団の装備・速度などで変わるため、従来どおり各師団・各候補の `estimateGarrisonTravelDays` で計算する。
- キャッシュ結果はコピーして返し、候補の処理による経路配列の書き換えが、後続の計画結果に波及しないようにする。
- シミュレーションのTick、戦争・領土支配・通行権の変化をまたいでキャッシュを再利用しない。グローバルなMapを作らない。

## Capabilities
- 同じ出発州・同じ防衛目標に対する重複陸路探索を計画内で省略する。
- 到達不能な目標への繰り返し探索も省略し、現在の経路合法性と決定論的な配置結果を維持する。

## Impact
- 対象: `src/engine/military/garrisonRouteCache.ts`、`garrisons.ts`、`garrisonBatchOptimization.ts` と統合テスト。
- 非変更: `findPath` の通行条件・A*探索・移動日数モデル・毎週最大4命令・守備隊の保護・セーブ形式・外部API・UI。
- 期待される改善: 同一州に複数師団が集まるケースでは合法経路の重複検索回数を削減する。実際の実行時間やメモリの増減は実測値がないため未確定。
- 性能限界: すべての師団が異なる出発州ならキャッシュによる削減は小さい。州×目標の候補数自体を制限する変更ではない。
- リスク: 経路を長期間キャッシュすると外交・支配権の変化後に誤った経路が残る。計画関数のローカルMapに閉じ、呼び出し間で破棄する設計で回避。
- 代替案: (1) WorldStateグローバルキャッシュは失効制御が必要なので不採用。(2) 経路探索の上限を下げると重要防衛地点の探索を打ち切るため不採用。(3) 単一計画内のローカルキャッシュは既存挙動への影響が小さいため採用。
- ロールバック: キャッシュlookupを各 `findPath` 呼び出しへ戻せば既存挙動へ復帰できる。
