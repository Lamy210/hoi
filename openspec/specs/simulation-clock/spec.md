# simulation-clock 仕様

## Purpose
固定Tickによる時間進行、日付管理、一時停止と速度切替を担う能力である。全システムの実行周期（日次・週次・月次）の基準となる時間の単一の真実源であり、実環境の時刻に一切依存しない決定論的な進行を提供する。

## Scope
### 責務
- 1 tick = 1日の固定進行とシナリオ開始日（epoch）からの経過管理
- プロレプティック・グレゴリオ暦による整数日付変換（表示用）
- 一時停止と速度段階（×1〜×8）の状態管理
- コマンドのtick境界適用の保証

### 非責務
- レンダリングのフレームタイミング（UIスレッド）
- システムのcadence定義（game-coreスケジューラ）
- 実レートの性能抑制の実装（依頼はするが測定はbench）

## Data Model
- `tick: i64`（epochからの日数）、`epochDate: {year,month,day}`、`speed: 0|1|2|4|8`、`paused: bool`
- 日付は `civilFromDays / daysFromCivil` の整数演算のみ。`Date` オブジェクトはシミュ内で使用禁止。

## State & Transitions
- 速度: `×1 ↔ ×2 ↔ ×4 ↔ ×8`、一時停止 `paused ↔ running`
- 重要イベント時の自動一時停止は「設定で無効化可能」な要求として機能する。

## Calculation Rules
- 日付 = epochDate + tick（整数）。月次境界は `tick % 30 == 0`（30日月の簡略化をシナリオが宣言できる）。
- 進行レートの目標は ×N（N日/秒）。実レートが予算tick時間を超えた場合は自動抑制しUIへ警告を出す（性能の保証ではなく状態の公開）。

## Invariants
- 同一tick内で日付が2回進むことはない。一時停止中にtickが進むことはない。
- 日付変換は決定論的（環境に依存しない）。

## Use Cases
- プレイヤーが×8で平時を加速し、開戦で自動一時停止→×1へ戻して細部確認。
- 月次集計システムが `tick % 30 == 0` を契機に実行される。

## Anomalies & Error Handling
- 負の速度・未知の速度値は拒否（検証エラー）。
- tickの巻き戻し（セーブ再開時）はスナップショット復元のみで実現し、進行中の巻き戻しは行わない。

## Dependencies
- 依存先: game-core（コマンド・スケジューラ）。
- 依存元: 全ドメインシステム（実行契機）、game-ui（時間UI）。

## Security & Performance
- 実時刻（`Date.now`等）をシミュに取り込まない（決定論）。速度抑制の判定のみに使用可。
- 1tick進行のコストは各システムの合計であり、clock自体はO(1)。

## Acceptance & Tests
- 日付変換の境界テスト（閏年・年跨ぎ・1936年〜2100年）。
- 速度切替時に進行が連続（tick欠落・重複なし）であることのテスト。

## Requirements

### Requirement: 固定Tick進行
clockは1tickを1日として、コマンド適用後にtickを進めなければならない（SHALL）。日付は整数演算で求められ、実環境の時刻に依存してはならない（SHALL NOT）。

#### Scenario: 進行と日付の整合
- **WHEN** epochを2026-01-01として100tick進める
- **THEN** 表示日付は2026-04-10相当となり、tick数は100のまま

### Requirement: 一時停止と速度段階
clockは一時停止と速度段階（×1/×2/×4/×8）を提供し、一時停止中はtickが進行しないがコマンドの受付は継続しなければならない（SHALL）。

#### Scenario: 一時停止中の命令
- **WHEN** 一時停止中に部隊移動コマンドを発行する
- **THEN** コマンドはキューに受け付けられ、進行再開後の最初のtickで適用される

### Requirement: コマンドのtick境界適用
エンジンはコマンドをtick内の処理の前に適用しなければならず（SHALL）、同一tick内で適用順序が変わることがあってはならない（SHALL NOT）（受信順FIFO）。

#### Scenario: 同tick内の順序固定
- **WHEN** 同一tickに2つのコマンドが積まれた状態で進行する
- **THEN** コマンドは受信順に適用され、この順序はリプレイでも同一である
